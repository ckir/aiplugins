# opencode-ctl-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `opencode-ctl-mcp` plugin (engine crate `shared/opencode-ctl`, four host fronts, pairing launcher, two skills) so Claude Code, Qwen Code, Antigravity and OpenCode can drive an OpenCode worker session through 20 typed MCP tools.

**Architecture:** One library crate owns everything (`Engine<T: Transport, C: Clock>` wrapping an rmcp `#[tool_router]` server, a `CliTransport` that shells out to `opencode api`, the OpenAPI gate, the pairing contract and the launcher); four thin per-host binaries call `opencode_ctl::cli::dispatch`. The wait/tool state machines are built and tested first against an in-process `FakeTransport`, then the real CLI transport is proven against a mock `opencode` binary, then host guards, pairing, launcher, fronts and release wiring land in that order. A lifted `shared/proc-guard` crate carries the process-group / job-object kill guard shared with `ghidra-worker-ctl`.

**Tech Stack:** Rust 1.99 (stable; `std::fs::File::lock` needs 1.89+), rmcp 3.1 workspace dependency (locked 3.5.1), tokio, serde/serde_json, schemars 1.0, tracing + tracing-appender, lru, sha2, uuid, thiserror; `nix` (unix) and `windows` (windows) cfg-gated; bun for the OpenCode front's tests. No new crates.

**Spec:** `docs/specs/2026-10-18-opencode-ctl-mcp-design.md` (APPROVED, panel done at 1e5f9c7). Every contract below comes from it; where this plan decides something the spec left open, the decision is marked **PLAN DECISION**.

## Review Focus

Inputs the spec implies but no task's named test exercised at planning time; each gets the test named here, added to the owning task.

1. **A settings file saved with CRLF line endings** (Windows editor): keys must still parse; `settings_crlf_frontmatter` (Task 4).
2. **The service registration file exists but its pid is dead** (service crashed): a call must map to `SERVICE_DOWN`, not `AUTH_FAILED` or `CLI_ERROR`; `transport_dead_service_is_service_down` (Task 13, mock mode `service.status:fail` + `ECONNREFUSED` stderr).
3. **A `--param` value containing a newline or NUL**: refused with `INVALID_ARGUMENT` before any spawn; `hatch_param_value_rejects_newline_and_nul` (Task 9).
4. **`OPENCODE_CTL_HOME` pointing at a path with spaces** (and the wrapper script baking it in): wrappers must quote it; `wrapper_quotes_home_with_space` is part of the quoting test (Task 18).
5. **A worker turn whose anchor message was removed server-side** (`session.revert` via the TUI): the marker search never finds the anchor; rule (iii) applies (the newest message's `time.created` is the clock) and the state is `running` then `stalled`; `wait_anchor_vanished_uses_newest_message_clock` (Task 10).
