# opencode-ctl-mcp-qwen

A Qwen Code extension that lets Qwen delegate bounded work to an [OpenCode](https://opencode.ai) worker session
over MCP. It is the Qwen Code front of `shared/opencode-ctl`; the Claude Code and Antigravity fronts are
`opencode-ctl-mcp-cc` and `opencode-ctl-mcp-agy`.

## Install

```console
$ bash scripts/install-qwen-extension.sh opencode-ctl-mcp-qwen
```

or build the binary locally:

```console
$ just build-opencode-ctl-mcp-qwen
```

The `opencode` executable is looked up on `PATH`, then in `~/.opencode/bin`; set `OPENCODE_CTL_BIN` to use
another. The server starts and handshakes even when `opencode` is not installed; the tools then answer
`OPENCODE_NOT_FOUND`.

## Tools

Twenty MCP tools (service lifecycle, sessions, prompt/wait/interrupt, messages and changes, permission and form
replies, `opencode_operations`, `opencode_api`, `pair_status`). `session_wait` blocks for one slice of
`wait_timeout_s` (120 s by default); `qwen-extension.json` sets the server `timeout` to 330000 ms.

## Layout

```
qwen-extension.json   manifest and MCP server registration
QWEN.md               context file
src/main.rs           thin main: all behaviour is in shared/opencode-ctl
skills/               opencode-ctl-driver, opencode-ctl-doctor (generated)
tests/                e2e against a mock opencode; skill copy check
```

The skill copies are generated by `opencode-ctl-qwen-mcp emit-skill <name> --host qwen` and pinned byte for byte
by `tests/skill_emit.rs`.

## Testing

```console
$ cargo test -p opencode-ctl-mcp-qwen
```

The tests drive the real `serve` over stdio against `mock-opencode-ctl-qwen` (a fake `opencode`); no real
`opencode` is run and the real home is never touched.
