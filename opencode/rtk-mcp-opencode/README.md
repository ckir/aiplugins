# rtk-mcp-opencode

An OpenCode V2 plugin that wires [`rtk`](https://github.com/ckir/rtk) (Rust Token
Killer) into every shell command OpenCode runs, for 60–90% fewer output tokens on
ordinary dev operations — plus rtk's analytics as MCP tools.

It is the OpenCode member of a family: `claude-code/rtk-mcp-cc` does this for
Claude Code and `qwen/rtk-mcp-qwen` for Qwen Code. The rewriting engine and the
MCP server binary are shared with the Claude Code sibling; only the host
integration (this `plugin.ts`) is OpenCode-specific.

Tested with OpenCode **v2.0.20** and `@opencode/plugin` **2.0.21**. The V2 plugin
API is explicitly beta and will churn — re-test on bump.

## How it works

OpenCode's `execute.before` hook hands the plugin the tool input as a mutable
event, so the plugin can rewrite a shell command before it runs. `rtk` already
speaks the Claude hook schema natively:

```console
$ echo '{"tool_name":"Bash","tool_input":{"command":"cat README.md"}}' | rtk hook claude
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecisionReason":"RTK auto-rewrite",
 "updatedInput":{"command":"rtk read README.md"}}}
```

So this plugin **owns no rewriting logic**. On `execute.before` for the `shell`
tool it builds that same `{"tool_name":"Bash","tool_input":{"command":…}}`
envelope from the event, pipes it to `rtk hook claude`, and applies the
verdict's `hookSpecificOutput.updatedInput.command` back onto the mutable event
input. Re-implementing the rewrite here would duplicate knowledge rtk owns and
drift the moment rtk changes.

### Fail-open, always

The hook writes nothing back when it has no opinion, and the command then runs
exactly as written. A missing, broken, or slow `rtk` therefore costs you
nothing.

Specifically, the command passes through untouched when the plugin is disabled,
the command is empty, rtk is not installed, rtk exits non-zero, rtk emits
anything that is not JSON, or the verdict is empty. Non-`shell` tools are never
touched.

## Prerequisites

`rtk` on your `PATH` (or `RTK_BIN` pointing at it). Verify with:

```bash
rtk --version   # should print: rtk 0.45.0 (or newer)
```

Without it the plugin installs and runs fine — it simply never rewrites
anything. Note the name collision: if `rtk gain` fails, you may have
reachingforthejack/rtk (Rust Type Kit) installed instead.

## Installing

The plugin is a file copy — no registry, no build of the TypeScript itself:

**Project-local** (one project):

```bash
cp opencode/rtk-mcp-opencode/plugin.ts .opencode/plugins/rtk-mcp-opencode.ts
cp -r opencode/rtk-mcp-opencode/skills/. .opencode/skills/
# merge opencode/rtk-mcp-opencode/opencode.jsonc into .opencode/opencode.jsonc
```

**Global** (every project): the same three copies under
`~/.config/opencode/` — `plugins/rtk-mcp-opencode.ts`, `skills/…`, merged into
`opencode.jsonc`.

A copied `plugin.ts` auto-loads — no `plugins` entry is needed for the standard
path. The `{ "package": … }` file-URL form is only for working-copy dev against
a checkout.

The MCP server needs its binary. `rtk-cc-mcp` is a `[[bin]]` of the existing
`rtk-mcp-cc` crate, staged by:

```bash
just build-rtk-mcp-opencode
```

That builds `rtk-cc-mcp` into `opencode/rtk-mcp-opencode/bin/`
(which is gitignored); release builds for all platforms come from CI via
`cargo-dist`. Alternatively, unpack `rtk-mcp-cc-plugin.zip` from the latest
release, which carries the binaries for every supported platform. Either way,
stage the built (or release-unpacked) binary at `.opencode/bin/rtk-cc-mcp` next
to the snippet's merge target — the `./bin/rtk-cc-mcp` command in
`opencode.jsonc` is relative to the installed plugin copy.

## Configuration

See `examples/rtk-mcp-opencode.local.md` for the full table. In short — copy it
to `.opencode/rtk-mcp-opencode.local.md`, or use the environment, which takes
precedence:

| Variable | Effect |
|---|---|
| `RTK_BIN` | Path to the rtk executable. Shared with `rtk-mcp-qwen`. |
| `RTK_OPENCODE_DISABLE=1` | Pass every command through untouched. |
| `RTK_OPENCODE_ULTRA_COMPACT=1` | Pass `--ultra-compact` to rtk. |
| `RTK_OPENCODE_SKIP_ENV=1` | Pass `--skip-env` to rtk. |

The `.local.md` file uses frontmatter keys `enabled`, `rtk_bin`,
`ultra_compact`, `skip_env` — the exact keys the plugin parses.

## MCP tools

| Tool | Runs a command? | Purpose |
|---|---|---|
| `rtk_gain` | no | Token-savings summary, optionally with per-command history |
| `rtk_discover` | no | Commands that could have been optimized but were not |
| `rtk_check` | no | How rtk *would* rewrite a given command — the way to answer "why did my command change?" |
| `rtk_proxy` | **yes** | Runs a command unfiltered but still tracked |

`rtk_proxy` is the one tool here that executes. It takes an **argv vector**, not
a shell line — `["git", "status"]`, not `"git status"` — and spawns it directly,
so no pipe, redirect, glob or `;` is ever interpreted. Prefer the ordinary
`shell` tool unless you specifically need to bypass rtk's rewriting while keeping
the command in rtk's statistics.

`rtk gain --reset` is deliberately unreachable: it zeroes the user's saved
statistics, and an MCP tool that can silently destroy data is not worth the
convenience.

## Testing

```bash
bun install && bun test tests/
```

The suite drives the hook's fail-open matrix (disabled, empty, missing binary,
non-zero exit, non-JSON output) against a mock `rtk` on `PATH`, so it runs
identically on a machine that has never had rtk installed.
