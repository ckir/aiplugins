# aiplugins-devtools-opencode

An OpenCode plugin that ships five dev-tool skills:

- `code-review-and-quality`, a multi-axis code review (correctness, readability,
  architecture, security, performance) with security and performance checklists.
- `spec-panel-review`, an adversarial multi-seat review of a spec or an
  implementation plan (not code), report-only.
- `human-friendly`, rewrites a Markdown file in place so it reads naturally,
  keeping code, links, tables, numbers and meaning intact. Supports
  `--review-only`, `--dry-run` and `--profile natural-professional|conversational|executive`.
- `license-headers`, adds or enforces per-file license headers with google/addlicense for
  custom or source-available licenses (header text read from your template file), with a
  `LICENSE-ADDENDUM` template for extra terms. Bundles a wrapper script; needs `addlicense`.
- `rust-toolchain-scaffold`, scaffolds a tested quality toolchain into a Rust repository: just
  recipes, lefthook hooks, rustfmt, clippy, nextest, cargo-deny, typos, gitleaks, SHA-pinned CI and
  CODEOWNERS, plus tests that prove each gate blocks. Its checks need `just`, `lefthook`, `gitleaks`, `cargo-nextest`, `cargo-deny` and `typos`.

Slash commands: `/spec-panel-review <path>`, `/human-friendly <path>`, `/license-headers <request>` and `/rust-toolchain-scaffold <request>` (command files; see Invocation).
It carries only skills: no plugin code, no hooks, no MCP servers, no binaries.

## Installation

See [INSTALL.md](INSTALL.md). It is a file copy of the skill folders into
OpenCode's `skills/` directory and of the command file into its `command/`
directory; there is no `opencode.jsonc` to merge.

## Invocation

OpenCode keys a skill by its folder name, so here the skills are invoked as
`aiplugins-devtools-code-review-and-quality` and
`aiplugins-devtools-spec-panel-review`, `aiplugins-devtools-human-friendly`, `aiplugins-devtools-license-headers` and `aiplugins-devtools-rust-toolchain-scaffold`. OpenCode also does not list skills in
its `/` menu, so the plugin ships command files, `commands/spec-panel-review.md`, `commands/human-friendly.md`, `commands/license-headers.md` and `commands/rust-toolchain-scaffold.md`;
`/spec-panel-review <path>`, `/human-friendly <path>`, `/license-headers <request>` and `/rust-toolchain-scaffold <request>` load the skill and run it on the argument. A colon is not valid in a folder
name, so the `aiplugins-devtools:` form used on the other agents is not
available on OpenCode.

### Context footprint

Installing this plugin adds **≥ 1,799 bytes** to every request, for the whole session. A further **≥ 52,364 bytes** load only when one of its skills or agents is actually invoked.

| Tier | Bytes | When you pay it |
|---|---|---|
| Resident | ≥ 1,799 | Every request, for the whole session |
| Invocation | ≥ 52,364 | Only when that skill or agent runs |

**Bytes, not tokens.** This is the exact serialised size of what the host loads, measured by probing the plugin's own MCP server and reading its skill and agent frontmatter. It is not a token count and does not convert to one at a fixed rate — treat it as a figure you can compare between plugins, not as a context budget.

**≥, because hook output is excluded.** Measuring it would mean executing the plugin's hooks against a synthetic event, which this tool will not do. A plugin whose hooks emit a large preamble costs more than the figure shown.
