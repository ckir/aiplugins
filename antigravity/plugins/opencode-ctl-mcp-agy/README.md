# opencode-ctl-mcp-agy

An Antigravity plugin that lets the agent delegate bounded work to an [OpenCode](https://opencode.ai) worker
session over MCP: start and inspect the OpenCode service, create sessions, send prompts, wait for the turn,
read the messages and the changes, and answer permission and form requests. A launcher pairs an OpenCode TUI
with the Antigravity session so a human can watch the worker.

It is the Antigravity front of `shared/opencode-ctl`; the Claude Code and Qwen Code fronts are
`opencode-ctl-mcp-cc` and `opencode-ctl-mcp-qwen`.

## Install

1. Download the versioned plugin bundle and extract it. The zip is named `<package>-agy-plugin.zip`:

   ```bash
   curl -fsSL -o /tmp/opencode-ctl-mcp-agy-agy-plugin.zip \
     https://github.com/ckir/aiplugins/releases/download/opencode-ctl-mcp-agy-v0.1.0/opencode-ctl-mcp-agy-agy-plugin.zip
   unzip -q -o /tmp/opencode-ctl-mcp-agy-agy-plugin.zip -d /tmp/opencode-ctl-mcp-agy
   ```

   The zip carries the plugin files plus the binaries for every supported platform, so nothing is compiled at
   install time. (From a checkout, `just build-opencode-ctl-mcp-agy` builds the binary locally.)

2. Install the plugin from the extracted directory:

   ```bash
   agy plugin install /tmp/opencode-ctl-mcp-agy
   ```

3. Put the installed `bin/` on `PATH`. `mcp_config.json` names the bare binary `opencode-ctl-agy-mcp`; the host
   resolves it through `PATH` and does not add the plugin's `bin/` itself. Then confirm:

   ```bash
   agy plugin validate <installed plugin directory>
   ```

The `opencode` executable is looked up on `PATH`, then in `~/.opencode/bin`; set `OPENCODE_CTL_BIN` to use another.
The server starts and handshakes even when `opencode` is not installed; the tools then answer `OPENCODE_NOT_FOUND`.

## First use

Ask the agent to delegate a task to opencode, or run the `opencode-ctl-doctor` skill to check the installation.
The `opencode-ctl-driver` skill carries the delegate-and-verify workflow.

## MCP tools

| Tool | Purpose |
|---|---|
| `service_status`, `service_start`, `service_stop`, `service_restart` | OpenCode service lifecycle (`service_stop` needs `confirm`) |
| `session_list`, `session_create`, `session_get`, `session_delete` | Sessions |
| `session_prompt`, `session_wait`, `session_interrupt` | Run a turn, wait in slices, interrupt |
| `session_messages`, `session_changes`, `workspace_status` | Read results |
| `permission_reply`, `form_reply`, `saved_permissions` | Answer worker requests |
| `opencode_operations`, `opencode_api` | Discover and call any OpenCode API operation |
| `pair_status` | State of the paired TUI |

`session_wait` blocks for one slice of `wait_timeout_s` (120 s by default); the host's MCP tool timeout must
allow at least that long.

## Launcher

`opencode-ctl-agy-mcp install-launcher` links `opencode-pair` into a directory on `PATH`; `opencode-pair`
(or `opencode-ctl-agy-mcp pair`) starts an OpenCode TUI paired with the Antigravity session, `resume` and
`attach` reconnect to an existing pair, and `gc` removes stale pair records.

## Layout

```
plugin.json                  manifest
hooks.json                   empty: this plugin installs no hooks
mcp_config.json              registers `opencode-ctl-agy-mcp serve`
src/bin/mcp.rs               thin main: all behaviour is in shared/opencode-ctl
skills/                      opencode-ctl-driver, opencode-ctl-doctor (generated, see below)
tests/                       e2e against a mock opencode; skill copy check
```

The skill copies are generated by `opencode-ctl-agy-mcp emit-skill <name> --host agy` and pinned byte for byte by
`tests/skill_emit.rs`.

## Testing

```console
$ cargo test -p opencode-ctl-mcp-agy
$ just agy-validate
```

The tests drive the real `serve` over stdio against `mock-opencode-ctl-agy` (a fake `opencode`); no real
`opencode` is run and the real home is never touched.
